# 2. NON-NEGOTIABLE RULES

## RULE 1 — NEVER INSPECT OR LEARN FROM THE TEST DATA

This is an absolute requirement.

Treat the Kaggle test dataset as completely unseen throughout development.

You must NOT:

1. Perform EDA on test features.
2. Analyze test-feature distributions.
3. Calculate statistical properties of the test dataset.
4. Perform train-test distribution comparisons.
5. Use test data for feature engineering.
6. Use test data for feature selection.
7. Fit scalers, imputers, encoders, PCA, or other transformations using test data.
8. Tune hyperparameters based on test data.
9. Use pseudo-labeling.
10. Use transductive learning.
11. Combine training and test datasets for preprocessing.
12. Use test predictions to revise model-selection decisions.
13. Attempt to infer hidden test targets.
14. Exploit the public leaderboard to reverse-engineer target values.

Use **training data only** for all modeling decisions.

During cross-validation, fit every statistical preprocessing operation separately within each training fold.

The test dataset may be loaded only after the final model is selected, solely for prediction generation.

At inference, perform only the minimum necessary schema and prediction-validity checks.

Never revise the selected model based on the test dataset.

## RULE 2 — PREVENT OVERFITTING AT ALL COSTS

Overfitting prevention must guide every modeling decision.

Do not blindly maximize training R² or minimize training RMSE/MAE.

For example:

Model A:
- Training RMSE = 0.12
- Validation RMSE = 0.95

Model B:
- Training RMSE = 0.68
- Validation RMSE = 0.82

Model B has stronger validation performance despite worse training performance.

Prefer models demonstrating:

- Low validation error
- Acceptable training-validation gaps
- Stable cross-validation results
- Low sensitivity to random seeds
- Robustness to moderate data perturbations
- Appropriate regularization
- Sensible model complexity
- Stable performance across relevant target ranges

A small train-validation gap alone does not guarantee strong generalization.

If additional model complexity improves training performance without credible validation improvement, reject that complexity.

## RULE 3 — PREVENT ALL DATA LEAKAGE

Investigate and prevent:

- Target leakage
- Data contamination
- Duplicate-record leakage
- Group leakage
- Temporal leakage
- Leakage through preprocessing
- Leakage through target encoding
- Leakage through feature selection
- Leakage through target transformations
- Leakage through stacking
- Leakage through full-data feature importance
- Leakage through repeated tuning against holdout data

Every supervised feature transformation must be learned using training folds only.

For target encoding and related supervised encodings, use cross-fitting and appropriate smoothing.

## RULE 4 — THE OFFICIAL KAGGLE METRIC IS THE PRIMARY OBJECTIVE

First determine whether the competition uses:

- RMSE
- MAE
- MSE
- RMSLE
- MSLE
- R²
- MAPE
- SMAPE
- Quantile loss
- A custom competition metric

Optimize the official metric rather than an unrelated score.

If RMSE is the objective, investigate large prediction errors and outliers carefully.

If MAE is the objective, prioritize robust methods and understand the effect of conditional-median prediction.

If RMSLE is used, analyze the target domain, non-negativity constraints, and whether target transformations are appropriate.

If the competition uses a custom metric, implement and validate that exact metric.

Never assume that improving R² necessarily improves the official metric.

## RULE 5 — NO GUARANTEED LEADERBOARD RESULTS

Do not claim that any algorithm or ensemble will definitely achieve a specific test score.

Performance claims must be supported by actual validation experiments.

Do not invent training results, cross-validation results, or leaderboard scores.

## Important Considerations

1. Log transformations may reduce sensitivity to large target values.
2. Minimizing log-space error does not necessarily minimize original-scale RMSE.

4. Some transformations require strictly positive targets.
5. Non-negative target predictions may need explicit constraints.
6. Any transformation parameters must be fitted on training folds only.

Do not apply log1p automatically.
